## Context Summary

DocuFlow is a document processing system with OCR (DeepSeek vLLM), spatial tree builder, 16 DB tables, and AI services (auth, translation, summarization, keywords, etc.).

This session implemented a **Unified Extraction Layer** so DOCX, DOC, text PDFs, and scanned PDFs all feed into the same pipeline. Key fixes were also made to the tree builder (preface bug) and a `utils/soffice.py` utility was created.

## Key Decisions Made

| Decision | Rationale | Alternatives Considered |
|----------|-----------|------------------------|
| `utils/soffice.py` — part of repo, not `.agents/skills/` | Skills dir is external/transient; soffice.py must be reliably available | Keep in skills dir (rejected: not part of repo) |
| Two-pass PDF extraction (PyMuPDF + pdfplumber) | pdfplumber finds table bboxes; PyMuPDF does heading/font analysis. Spans inside table bboxes suppressed to avoid duplication | pdfplumber only (no font-size heading detection) |
| DOCX: direct XML walking (`body.findall`) not `doc.paragraphs` | Real Vietnamese CV docs store all content in `wps:txbx` drawing frames invisible to `doc.paragraphs` | python-docx paragraph API (fails on text-box docs) |
| DOCX fast-path in spatial builder: skip spatial scoring when all bboxes = 0 | DOCX elements have no pixel coordinates; spatial scoring is meaningless | Run spatial scoring anyway (produces wrong hierarchy) |
| Windows: fallback to `C:\Temp` for LibreOffice `--outdir` | LibreOffice silently fails (exit 1, no output) when `--outdir` path contains non-ASCII (e.g. `C:\Users\Duy''`) | Sanitize path (complex); use fixed temp dir (chosen) |

## Important Notes

- The **existing OCR pipeline** (`submit_ocr()` / `POST /{id}/ocr`) must remain untouched — it's the path for scanned PDFs/images submitted directly
- `_run_extraction()` is the NEW parallel path for DOCX/DOC/text-PDF — it calls the OCR pipeline internally for scanned pages of mixed PDFs
- The `UnifiedElement.to_layout_element_dict()` output format is designed to match exactly what `build_spatial_tree()` expects — verified in earlier session
- All extractors import `UnifiedElement` from `core.models` and `BaseExtractor` from `services.extractors.base`
- `DocxExtractor` uses **no bbox** (all None) → triggers DOCX fast-path in spatial builder (checks `if not any(e.get('bbox_x1', 0) for e in elements)`)
